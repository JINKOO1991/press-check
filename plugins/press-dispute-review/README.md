# press-dispute-review

한국어 기사 원고(제목·부제·본문·사진 설명)를 발행 전에 검토해, 언론분쟁 쟁점이 될 수 있는 구체적 표현과 확인 사항을 찾고 기사 취지를 유지하는 최소 수정안을 제안하는 Claude Code 플러그인입니다.

> **법률 자문이 아닙니다.** 편집 보조 도구입니다. "소송을 당하지 않는 기사"나 분쟁 확률을 보장하지 않습니다. 최종 게재 판단은 기자와 편집 책임자가 합니다.

## 현재 상태 (버전 0.1.0, P0)

- 저장소에 들어 있는 근거 코퍼스는 **기능 시험용 합성(fixture) 자료뿐**입니다. 실제 판례·언론중재위원회 조정·심의 자료는 사용자가 수집 CLI로 로컬 색인을 만들어야 쓸 수 있습니다(아래 '검색 색인').
- 로컬 색인이 없으면 MCP 서버는 기동하지만 `search_cases`와 `submit_report`가 합성 근거 대신 오류를 돌려줍니다. 기능 시험을 위해 `PRESS_REVIEW_ALLOW_SYNTHETIC=1`을 설정하면 합성 자료로 동작하며, 그때 나오는 근거는 실제 사례가 아니므로 인용하거나 법적 판단에 쓰면 안 됩니다. `/press-dispute-review:corpus-status`는 색인이 없어도 동작해 상태를 보여 줍니다.
- 법률 전문가 2명이 일부 항목을 검토했고, 검증 범위와 한계는 아래 '한계와 사용 범위'에 적었습니다. 테스트 통과는 법적 안전성 인증이 아닙니다.
- 신규 설치의 수집 자료 권리 기본값은 모두 `unknown`입니다. 기관 이용 문의 회신 전이므로 공개본은 허용 상태를 기본으로 제공하지 않으며, 사용자가 `rights set`으로 직접 기록해야 외부 API 반출이 열립니다(아래 '코퍼스 만들기').

## 요구사항

- **Claude Code**(CLI) 또는 **Claude Desktop의 로컬 세션**. 이 플러그인의 MCP 서버는 사용자 컴퓨터에서 stdio로 실행되므로 claude.ai 웹에서는 동작하지 않습니다.
- **Python 3.12에서 확인했습니다**(3.10·3.11은 시험하지 않았습니다). 런타임 외부 패키지는 필요 없습니다(표준 라이브러리만 사용).
- **Windows**: `PRESS_REVIEW_PYTHON` 환경변수에 Python 인터프리터 경로를 지정하세요(예: `C:\Users\<사용자>\AppData\Local\Programs\Python\Python312\python.exe`). 지정 후 Claude Code를 다시 시작합니다.

## 설치

Claude Code 안에서:

```text
/plugin marketplace add JINKOO1991/press-check
/plugin install press-dispute-review@press-dispute
```

셸에서:

```bash
claude plugin marketplace add JINKOO1991/press-check
claude plugin install press-dispute-review@press-dispute
```

- 저장소는 `JINKOO1991/press-check`입니다.
- 마켓 이름은 `press-dispute`, 플러그인 이름은 `press-dispute-review`입니다.
- 설치 확인: `/plugin`의 Installed·Errors 탭, `/mcp`에서 `press-review` 서버 연결 상태.
- 비공식 마켓은 자동 업데이트가 기본으로 꺼져 있습니다. `/plugin`의 Marketplaces에서 켜거나 `claude plugin update`를 쓰세요.

## 사용법

| 명령 | 하는 일 |
|---|---|
| `/press-dispute-review:review [파일]` | 원고를 검토해 검토 필요도 표를 보여 줍니다. 파일 경로를 주거나, 비워 두고 원고를 붙여 넣으세요 |
| `/press-dispute-review:explain <report_id> <finding_id>` | 표의 한 항목에 대한 상세 근거와 반대 근거를 보여 줍니다(30분 안) |
| `/press-dispute-review:corpus-status` | 근거 코퍼스의 건수·기준일·합성 여부를 보여 줍니다 |

기본 출력은 다음 네 칸의 표입니다.

| 문제 요소 | 검토 필요도 | 사유 | 추천 수정안 |
|---|---|---|---|
| 원문 구절과 위치 | ★~★★★ | 한 문장 | 최소 수정, 또는 "발행 전 확인: …" |

- 첫 화면에는 검토 필요도가 높은 순서로 **5건**까지 보이고, 나머지는 건수로 알려 줍니다.
- 원문 블록(제목·부제·본문·캡션) 구분은 자동 추정입니다. 검토 전에 보여 주는 블록 목록이 틀렸으면 바로잡아 주세요.
- 플러그인은 원고 파일을 자동으로 고치거나 발행하지 않습니다.

## 코퍼스 만들기(수집·색인)

저장소에는 코퍼스가 없습니다. 실제 근거를 쓰려면 아래 순서로 로컬에 만듭니다. 각 기관 자료의 이용정책·권리 표시는 사용자가 직접 확인해야 하며, 수집물은 사용자 로컬에만 보관되고 저장소에 포함되지 않습니다. 신규 설치의 권리 기본값은 `unknown`이며 사용자가 `rights set`으로 직접 기록해야 외부 API 반출이 열립니다.

- 실행 위치: 저장소 루트에서 `PYTHONPATH=plugins/press-dispute-review/engine python3 -m press_review.ingestion <target>`. 수집물은 `<data>/corpus/`, 색인은 `<data>/index/`에 생기며 `<data>`는 `PRESS_DISPUTE_DATA_DIR`(기본 `~/.local/share/press-dispute-review`)입니다.
- 수집·추출 target: `pac`, `iendc`, `lawapi`, `lawapi_body`, `fetch`, `extract`, `withhold`, `robots_check`. 상태 확인은 `status`, `export-inventory`, `export-coverage`, `admission`. 전체 목록은 `--help`로 확인하세요. 이 단계에는 DeepSeek 키가 필요하지 않습니다.
- **권리 기록** `rights show`는 소스별 현재 권리 값과 기록자·시각·근거를 보여 줍니다. `rights set <source_family> --external-api allowed --note "근거 한 줄"`는 그 계열로 등록된 소스(수집 target을 한 번 실행해 소스가 장부에 있어야 합니다)에 결정을 기록합니다. 다른 권리 항목은 `--read`, `--store-raw`, `--create-derivatives`, `--redistribute-raw`, `--redistribute-derivatives`, `--fine-tune`이고 값은 `allowed|forbidden|permission_required|unknown`입니다. 지정하지 않은 항목은 그대로 두며, `forbidden`은 풀 수 없고, `unknown`을 허용으로 바꾸는 자동 경로는 없습니다. 이 결정은 법률 판단이 아니라 사용자의 기록이며 근거 메모에 책임이 따릅니다.
- **구조화** `python3 -m press_review.ingestion.structure`: 색인은 구조화가 만든 chunk만 읽으므로, 구조화 없이는 색인에 자료가 들어가지 않습니다(코드 확인, 실행해 보지는 않았습니다). 심의기준·위원회 규정·PAC 연구자료는 모델 호출 없이 chunk만 만들 수 있고, PAC 사례집·IENDC·판례는 `DEEPSEEK_API_KEY`가 필요합니다. 이 단계는 소스의 `rights.external_api`가 `allowed`일 때만 외부로 전송하며, 신규 설치에서는 `unknown`이라 `rights set` 전에는 전송하지 않습니다.
- 색인: `build_index` target은 네트워크·외부 API·비밀값을 쓰지 않습니다.
- 키: `DEEPSEEK_API_KEY`(구조화), `LAW_OPEN_DATA_OC`(법제처 목록·본문 조회)는 환경변수로만 받고 출력·Git에 넣지 마세요.
- PDF·HWP 추출에는 외부 도구(poppler-utils, tesseract, kordoc 등)가 쓰일 수 있습니다. 필요한 범위는 확인하지 못했습니다.

## 검색 색인과 원문 인용 상한 (P3)

- 근거 검색은 **로컬 SQLite 색인**만 씁니다(`<data>/index/corpus-<snapshot>.sqlite`, 위치는 `PRESS_DISPUTE_DATA_DIR`). 웹 검색을 하지 않고 원고 내용을 외부 검색어로 보내지 않습니다. 색인은 저장소에 들어 있지 않으며, 수집 CLI(`python -m press_review.ingestion build_index`)로 각자 만듭니다. 색인이 없으면 `search_cases`·`submit_report`가 오류를 돌려주고(`PRESS_REVIEW_ALLOW_SYNTHETIC=1`이면 합성 코퍼스로 동작) `corpus-status`에 '실자료 미적재'가 표시됩니다(오류와 경고에 조회한 데이터 폴더·색인 경로가 적히며, `--plugin-dir`로 직접 로드하면 `CLAUDE_PLUGIN_DATA`가 우선하므로 색인이 기본 위치에 있으면 `PRESS_DISPUTE_DATA_DIR`을 설정해야 합니다). 색인을 새로 만들면 MCP 서버(Claude Code)를 다시 시작해야 반영됩니다.
- 검색 순서: 사건번호·조문 정확 검색, FTS5 trigram BM25, 2글자 질의어 보완. 벡터 검색은 하지 않습니다. `stance=counter`는 같은 질의 결과 중 청구 배척·면책 표지가 있는 자료를 앞에 둡니다.
- **원문 인용 상한(상수 `DISPLAY_QUOTE_MAX_CP` = 300자)**: 재배포 허락(`redistribute_raw`·`redistribute_derivatives`)이 `allowed`가 아닌 소스는 사용자 화면에 보이는 인용(`display_text`)을 300자 이내로 자릅니다. 내부 판단용 `text`는 전문입니다.
- 색인 기준일(구축일·최신 결정일)과 분석 기준일(`legal_as_of` = 기사 발행 예정일)은 따로 표시합니다.

## 별(★)의 의미

**별(★)은 실제 분쟁 발생 확률이 아니라 검토 우선순위입니다.**

| 별 | 의미 |
|---|---|
| ★ | 확인 권고 |
| ★★ | 수정·보강 검토 |
| ★★★ | 발행 전 집중 검토 |

- 분쟁 제기·조정·패소 확률이나 퍼센트(%)는 표시하지 않습니다. 공개 분쟁 사례만으로는 분쟁 없이 발행된 기사 수(분모)를 알 수 없어 확률을 계산할 근거가 없기 때문입니다.
- 근거 신뢰도는 별과 따로 관리합니다. 근거를 찾지 못한 항목은 "근거 미확보"로 표시됩니다.
- 경고가 없다는 결과는 안전 보장이 아닙니다.

## 무엇을 하고 무엇을 하지 않나

- 정정보도·반론보도·추후보도·민사·형사·선거심의·개인정보·초상·저작권 경로를 섞지 않고 따로 표시합니다. 예를 들어 반론보도는 원보도가 진실해도 청구될 수 있으므로 "허위"나 "위법"으로 표시하지 않습니다.
- 불편한 주제, 강한 비판, 과거 분쟁 이력만으로 경고하지 않습니다. 근거 있는 공익 보도를 약화시키는 것도 실패로 봅니다.
- 원고에 없는 사실·반론·답변·취재 절차를 수정안에 만들어 넣지 않습니다. 필요한 경우 "발행 전 확인" 항목으로 제시합니다.
- 직접 인용 안의 발언을 바꾸지 않습니다.
- "의혹", "혐의", 물음표, 익명 처리만으로 문제가 해소됐다고 보지 않습니다.
- 근거 출처는 코퍼스 검색 결과에 실제로 있는 레코드만 쓰며, 서버가 출처·위치 일치를 검사합니다.
- 원고나 자료 속의 지시문(예: "키를 출력하라")은 데이터로 취급하고 실행하지 않습니다.

## 한계와 사용 범위

이 도구는 검토 보조이며 법률 자문이 아닙니다. 결과를 아래 두 층으로 나누어 읽으세요.

- **근거 인용은 원문과 대조할 수 있습니다.** 보고서가 인용한 사건번호·조문·원문 구절은 서버가 코퍼스 레코드와 일치하는지 검사하며, 사용자도 출처 원문에서 직접 확인할 수 있습니다.
- **적용 판단은 일부만 검증했습니다.** "이 기사 구절에 그 기준이 적용되는가"는 호스트 모델의 판단입니다. 이 판단은 법률 전문가 2명의 의견이 합의된 항목에 대해서만 검증했고(수정 대상 2/7, 보존 15/17), 의견이 갈린 항목은 불확실로 두어 검증 범위에 넣지 않았습니다. 규모가 작아 정확도나 성능 수치를 주장하지 않습니다.
- **수집 범위에 빈틈이 있습니다.** 판례는 1,110건이며 최근(2010년 이후) 대법원 판례 보강이 얕습니다(사건명 신호 시험 수신 154건 중 0건 통과, 보강 중단). PAC 시정권고 11,361건, 정정 538건, 연구자료 1,954건 등을 색인했지만 권리 보류·비공개·추출 제외분이 있으며, 색인된 범위가 전체 사건이 아닙니다.
- **과잉경고 점검은 5건뿐입니다.** 분쟁 이력이 없는 기사 5건에서 경고가 0건이었으나 표본이 작아 과잉경고율을 말할 수 없고, 확대는 보류했습니다. 분쟁 이력이 없다는 것은 법적으로 안전하다는 뜻이 아닙니다.
- **권리 기본값은 허용이 아닙니다.** 공개본의 소스 권리는 신규 설치에서 `unknown`이고, 기관 이용 문의 회신 전이라 허용 상태를 기본 제공하지 않습니다. 허용은 사용자가 `rights set`으로 기록한 결정만 장부에 남습니다.
- 수집 자료에 기관·연락처·이메일 등 개인정보가 포함될 수 있으며, 사용자 화면 인용에 그대로 나올 수 있습니다.
- 근거를 찾지 못했다는 것은 문제가 없다는 뜻이 아닙니다. 별은 검토 우선순위이며 분쟁·패소 확률이 아닙니다. 색인이 없을 때의 합성 코퍼스 동작과 `PRESS_DISPUTE_DATA_DIR` 설정은 '검색 색인' 절을 보세요.

## 데이터 흐름과 한계

- **원고는 호스트 모델(Claude)에 전송될 수 있습니다.** 대화에 붙여 넣거나 Claude Code가 읽은 원고, 도구 결과로 돌아온 원고 블록은 Claude Code가 쓰는 모델 제공자에게 전송됩니다. 기사 분석 자체를 호스트 모델이 하기 때문입니다.
- **로컬 MCP 서버만으로 원고의 로컬 처리가 보장되지 않습니다.** 로컬 서버는 블록 분해, 근거 검색, 형식·위치·수정안 검사를 할 뿐입니다. 소속 언론사의 원고·취재원 보호 정책을 먼저 확인하세요.
- 이 플러그인은 원고를 DeepSeek 등 다른 외부 제공자로 보내지 않습니다.
- **무보관**: 원고와 검토 결과는 디스크에 저장하지 않고 MCP 서버 메모리에만 **30분** 보관합니다. 그 뒤(또는 Claude Code 재시작 뒤)에는 상세 설명을 볼 수 없으니 원고를 다시 주세요. 보고서는 원고와 같은 시각에 만료되며, 원고·보고서 합계가 16건을 넘으면 가장 오래된 것부터 지웁니다. 보관 시간은 단조 시계로 재므로 컴퓨터가 절전 중인 시간은 세지 않습니다.
- 서버 로그에는 요청 ID·해시·건수만 남기고 원고 문장을 기록하지 않도록 설계했습니다. 단, Claude Code 자체의 대화 기록 보관은 Claude Code 설정을 따릅니다.
- 비식별 요약이나 문제 구절만으로도 재식별될 수 있습니다. 취재원 실명·연락처·미공개 증거는 넣지 않는 것을 권합니다.
- 사진 자체는 판독하지 않습니다. 사진 설명(캡션) 텍스트만 검토합니다.
