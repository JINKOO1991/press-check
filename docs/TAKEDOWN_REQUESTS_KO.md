# 자료 중단·삭제 요청 처리 절차

기관 또는 개인이 이 프로젝트의 코드·문서·자료 배포에 대해 중단이나 삭제를 요청할 때의 절차입니다. 법률 자문이나 법적 판단이 아니며, 요청의 법적 근거를 따져 거절하는 절차도 아닙니다. 기한은 결정 기록 UDEC-27(`docs/DECISIONS.md`)을 따릅니다.

## 접수

- 접수 경로는 GitHub 이슈입니다: https://github.com/JINKOO1991/press-check/issues
- 이슈에는 요청 대상(파일 경로, 자료 식별자 `source_id`·`passage_id`, 링크 중 해당하는 것)과 요청 내용만 적어 주세요. 삭제를 구하는 개인정보 자체(주민등록번호, 연락처, 주소 등)와 원고·취재원 정보는 이슈에 적지 마세요. 이슈는 공개됩니다.
- 제목에 `[중단·삭제 요청]`을 붙이면 구분하기 쉽습니다.
- 공개 이슈에 쓰기 어려운 요청은 저장소의 비공개 신고(GitHub Security 탭의 Report a vulnerability)로 보내 주세요. GitHub 계정이 필요합니다.

## 처리

1. 접수 사실을 이슈에 댓글로 남깁니다.
2. 접수일부터 7일 이내에 조치합니다. 조치는 대상 자료를 배포에서 빼거나, 해당 passage를 제거 목록에 올리거나, 문서의 해당 부분을 고치는 것입니다. 요청한 자료를 이 프로젝트가 배포하지 않으면 그 사실을 알립니다.
3. 조치가 7일 안에 끝나지 않는 사정이 있으면 7일 안에 그 이유와 예상 시점을 이슈에 적습니다.
4. 이미 내려받은 사용자의 로컬 색인과 복사본은 이 프로젝트가 지울 수 없습니다. 이 한계도 답변에 적습니다.

## 조치 기록

- 이슈 댓글에 조치 날짜, 조치 유형(삭제·제거 목록 추가·문서 수정·미해당), 영향받은 파일 경로 또는 자료 식별자를 적습니다. 요청자의 개인정보와 삭제한 자료의 본문은 기록에 옮기지 않습니다.
- 코드·문서를 바꾸면 커밋 메시지에 이슈 번호를 적습니다.
- 자료 묶음(번들)에서 뺀 항목은 릴리스 설명의 제거 목록에 식별자와 판본 ID로 기록합니다.
