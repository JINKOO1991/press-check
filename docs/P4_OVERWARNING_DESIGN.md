## 1. 목표·비목표·해석 규칙

### 1.1 이 점검이 답하는 질문

- **Q1(경고율 상한).** 분쟁 이력이 없는 실제 발행 기사에서 플러그인이 기사 단위로 ★≥2 경고를 얼마나 내는가. 경고는 어느 `issue_category`·`suggested_edit.mode`·분야·길이에 몰리는가.
- **Q2(라벨 없이 판정 가능한 중대 실패).** 수정안이 원고에 없는 사실(숫자·반론 요청·응답·동의·취재 사실)을 더하는가. 직접 인용을 바꾸는가. 확률 표현을 쓰는가.

보조 산출물로, 판독(§5)에서 '명백한 과잉'으로 분류된 경고의 비율을 과잉 경고의 **하한 진단치**로 낸다. Q1의 경고율이 상한이고 이 진단치가 하한이다. 둘 사이 어디에 실제 과잉 경고율이 있는지는 이 점검으로 정하지 못한다.

Q2는 정답 라벨 없이 판정된다. P4_DESIGN §7.1의 중대 실패(무단 사실 추가·직접인용 변조·% 표시)는 경고가 정당했는지와 무관하게 실패이기 때문이다. 이 점검에서 가장 해석이 단단한 결과다.

### 1.2 해석 규칙

1. **'분쟁 이력 없음'은 '문제 요소 없음'이 아니다.** 분쟁이 없었다는 것은 제기되지 않았다는 뜻이다. 이 풀에서 나온 경고 일부는 정당할 수 있다. 그래서 관측 경고율 W는 과잉 경고율의 상한으로만 해석한다. "거짓 경고율"이라고 쓰지 않는다.
2. **라벨은 '분쟁 이력 없음' 하나뿐이다.** 근거는 사용자 진술(2026-10-16, 전수 확인)이다. 변호사 합의 라벨(수정 대상 2/7, 보존 15/17 일치분)과 같은 표·같은 분모에 섞지 않는다. 사용자(기자) 판단은 라벨이 아니다(2026-10-16 결정). 진단 메모로 쓸지는 §8 결정 5에서 정한다.
3. **별은 확률이 아니다.** 경고율을 분쟁·패소 확률로 바꾸지 않는다. 퍼센트 확률 기능은 계속 비활성이다. 이 보고의 비율은 표본 안 기사 비율이다.
4. **통과는 안전 인증이 아니다.** 경고율이 낮아도 "이 기사들은 법적으로 안전하다"거나 "플러그인이 과잉 경고하지 않는다"고 쓰지 않는다. 합격선은 두지 않는다. 결과는 보고 항목이고, 임계는 결과를 본 뒤 사용자가 정한다.
5. **외적 타당성 한계.** 기자 1명, 매체 1곳, 데스크 편집을 거친 발행 기사다. 프로젝트는 특정 기자 문체를 기본값으로 삼지 않는다(CLAUDE.md). 이 결과를 '국내 기사 일반'의 경고율로 일반화하지 않는다. 발행 전 원고보다 다듬어진 글이라 경고율이 낮게 나올 수 있다.
6. **분야와 시기를 가르지 못한다.** 분야 폴더가 부서 시기와 겹친다(§0). 분야 차이와 시기 차이를 분리해 해석하지 않는다. 오래된 기사는 `as_of`(발행일) 이전 색인 자료가 적어 근거 미확보 경고가 늘 수 있다. 연도별 차이에는 이 혼입이 있다.
7. **재지 않는 경고 원천.** 입력을 결정적 article JSON으로 넘기므로(§2.4) 실제 사용자가 평문을 붙여 넣을 때의 휴리스틱 블록 판정을 거치지 않는다. 블록이 잘못 나뉘어 생기는 경고는 이 점검에 잡히지 않는다.
8. **결과를 보고 SKILL을 고치면 그 기사들은 tune 자료가 된다**(P4_DESIGN §3.4). 고친 뒤의 재측정은 아직 쓰지 않은 중첩 확장분(§2.3)으로 한다.

### 1.3 비목표

- recall(놓친 쟁점) 측정. 이 풀에는 정답 쟁점이 없다.
- 경고 precision의 확정. 판독은 법률 라벨이 아니다(§5).
- 검색 품질, 근거의 법적 적합도.
- DeepSeek를 호스트로 쓰는 구성의 평가(§3.1 경로 E).

### 2.3 크기 옵션과 신뢰구간

기사 단위 비율 p의 95% Wilson 구간(유한모집단 보정 없음. n=300이면 F의 9%라 실제 구간은 약 5% 좁다):

| n | p=0(0건) | p=0.05 | p=0.10 | p=0.20 | p=0.40 |
|---|---|---|---|---|---|
| 30 | 0~11.4% | 1.8~21.3%(폭 19.5) | 3.5~25.6%(22.2) | 9.5~37.3%(27.8) | 24.6~57.7%(33.1) |
| 100 | 0~3.7% | 2.2~11.2%(9.0) | 5.5~17.4%(11.9) | 13.3~28.9%(15.5) | 30.9~49.8%(18.9) |
| 300 | 0~1.3% | 3.1~8.1%(5.0) | 7.1~13.9%(6.8) | 15.9~24.9%(9.0) | 34.6~45.6%(11.0) |

- 0건일 때 Wilson 상한은 3의 법칙(3/n)보다 조금 크다(n=100: 3.7% 대 3%). 보고에는 Wilson 값을 쓰고 3/n을 병기한다.
- 5% 기준과의 거리: n=100에서 1건이면 상한 5.4%, 2건이면 7.0%다. n=300에서 6건(2%)이면 상한 4.3%다. '상한 5% 미만'을 말하려면 n=100에서 0건이거나 n=300에서 약 2% 이하여야 한다.
- 분야별 추정은 n=100에서 칸당 4~29건이라 구간이 넓다. 분야 비교는 서술용이고 검정하지 않는다.
- finding 단위 분포(범주·경로 비율)는 한 기사 안 finding끼리 상관이 있어 기사 단위 부트스트랩(2,000회, 고정 시드)으로 구간을 낸다.

**중첩 추출(재현성).** 고정 시드(예: `overwarn-v1-20261017`의 sha256 앞 8바이트)로 칸마다 무작위 순열을 만든다. n=100 표본은 각 칸 순열의 앞부분이다. n=300 확장은 같은 순열의 다음 부분이라 기존 100건을 포함한다. 파일럿 5건은 별도 시드로 F에서 뽑고 본 표본에서 뺀다(하네스 디버깅에 쓴 tune 자료다). 시드·추출기 커밋·frame manifest sha256을 결과 meta에 기록한다.

### 2.4 입력 준비(본문 수정 금지)

- 기사 텍스트는 바꾸지 않는다. 허용하는 변경은 기자 표시 제거 하나뿐이다.
- 기자 표시 제거: 헤더 byline은 전달하지 않는다(어차피 1건 빼고 비어 있다). 본문은 끝부분의 포털 홍보 줄(▶로 시작, 3,372건 중 1,329건에 있음)을 먼저 떼고, 남은 **끝 3개 비공백 줄** 안의 이메일 주소와 '이름+기자' 서명 줄만 지운다(파일럿 2026-10-17에서 정정. 끝 3줄만 보면 홍보 줄 때문에 서명을 놓쳤다. 이 규칙으로 서명이 잡히는 기사 1,096건). 본문 중간의 이메일은 제3자 것일 수 있어 건드리지 않고 건수만 기록한다. 기사마다 지운 글자 수와 줄 수를 기록한다.
- 블록 구조는 결정적으로 만든다. 헤더 title → 제목 블록, subtitles 각 항목 → 부제 블록, 본문은 빈 줄 기준 문단 → 본문 블록. article.schema JSON으로 만들어 `prepare_article`의 `article`로 넘긴다(SKILL §1.1이 허용). 휴리스틱 블록 판정과 SKILL §1.4의 사용자 확인 단계를 피하고, 같은 입력이면 같은 `article_sha256`이 나온다.
- 캡션·사진 설명 줄이 본문에 섞여 있는지는 확인하지 않았다(본문을 읽지 않았다). 파일럿 5건에서 구조만 확인한다.
- 발행일: 헤더 `date`의 날짜를 `publication_date`로 넘긴다. 서버가 이를 `legal_as_of`로 쓰고 이후 자료를 근거에서 막는다. 발행 전 검토를 그 시점에 한 것으로 흉내 낸다.

### 3.2 권고 실행 구성(A1)

명령 골격이다. 플래그 조합은 파일럿에서 실제로 확인한다(§3.5).

```
timeout 900 claude -p "<고정 지시문>" \
  --bare --plugin-dir <저장소>/plugins/press-check \
  --model <고정 모델 ID> --effort <고정 effort> \
  --output-format stream-json --verbose --no-session-persistence \
  --permission-mode dontAsk \
  --allowed-tools "Skill mcp__plugin_press-check_press-review__prepare_article mcp__plugin_press-check_press-review__search_cases mcp__plugin_press-check_press-review__submit_report" \
  --disallowed-tools "Bash WebSearch WebFetch Agent Edit Write NotebookEdit" \
  --max-budget-usd <기사당 상한> < <입력 JSON>
```

- 작업 디렉터리: 저장소 밖 `~/.local/share/press-dispute-review/eval/overwarn/<run_id>/work/`.
- 환경: `PRESS_REVIEW_PYTHON`에 엔진 의존성이 있는 파이썬을 지정한다. 실행마다 MCP 서버가 새로 뜬다. 새 프로세스가 활성 snapshot을 읽는지 파일럿에서 확인한다.
- 웹 검색·셸·서브에이전트를 막는다. 원고 내용이 담긴 웹 질의는 P4_DESIGN §4.2의 전송 실패다.
- `--max-turns`가 없으므로 턴 상한 대신 기사당 비용 상한(`--max-budget-usd`)과 벽시계 상한(`timeout`)으로 묶는다. OAuth 경로에서 `--max-budget-usd`가 실제로 막는지는 확인하지 않았다.
- 동시 실행: 2~3. 속도 제한을 공유하므로 파일럿 뒤 정한다.
- 고정 지시문 원칙: 스킬 호출(`/press-check:review`), 입력은 article.schema JSON이며 `article`로 넘길 것, `publication_date` 값, 블록 확인 없이 진행할 것, 표 출력 뒤 종료할 것만 담는다. 이 기사가 분쟁 이력이 없다는 사실, 평가 목적, 분야 폴더는 알리지 않는다(맹검). 지시문 sha256을 meta에 기록한다. 지시문을 바꾸면 새 run_id다.

### 3.3 출력 추출

- `submit_report` 응답에는 보고서 본체가 없다(§0). 추출기는 stream-json에서 **마지막으로 성공한 `submit_report` tool_use의 입력**(findings·explanations·overall_status·coverage_notes)을 결과로 쓴다. 서버가 붙이는 verified·hidden_finding_count는 tool_result에서 따로 뽑는다.
- 기사당 압축 결과 JSON: run_id, 기사 키(로컬 순번), 호스트 기록(모델 ID·effort·Claude Code 버전·스킬 파일 sha256·플러그인 커밋·지시문 sha256·색인 snapshot), prepare 메타(article_sha256·블록 수·서버 경고), search 호출 수 k와 질의 목록, submit 시도 수와 서버 오류 코드, 최종 제출, 결과 메시지의 total_cost_usd·usage·num_turns·duration_ms·is_error·permission_denials.
- 원본 stream-json은 추출과 검증(§3.5 ③)이 끝나면 지운다(§6.3).
- 검색 호출 수 k의 분포는 P4_DESIGN §5.5 '기사당 search 호출 수'의 입력으로도 쓴다.

### 3.4 비용 추정

**2026-10-17 파일럿 실측으로 정정.** 구독 경로 Sonnet 5.5 high에서 실제 기사 5건(중앙값 이하 길이, 경고 0건)의 기사당 환산 비용은 $0.16~0.43, 평균 $0.263이었다. 턴은 4~8, 경과는 28~56초다. 이를 길이와 finding을 감안해 보정하면 기사당 중심 $0.30~0.45(범위 $0.16~0.80)다. Sonnet n=100은 중심 $30~45(범위 $16~80)이고, 아래 표의 $50~100(상단 $200)을 대체한다. 근거와 규모·effort별 표는 `docs/coverage/P4_overwarning_pilot.md` §4. Opus·Fable 행은 측정하지 않았다. 대략 Sonnet 실측의 2배, 5배로 본다(추정). 아래는 정정 전 원 추정으로 기록용이다.

선례: 이 플러그인 스킬을 실제로 돌린 기록이 없다(§0, tool_use 0건). 가장 가까운 측정은 이 프로젝트의 서브에이전트다. Sonnet 5.5는 8~20턴에 $0.21~0.58, Opus 5.5는 21~44턴에 $2.09~5.22였다. 다른 작업이고 출력 토큰이 덜 잡혔으므로 하한으로만 쓴다. 전역 CLAUDE.md에는 기사 1건 작업을 $0.6~3.5로 추정했는데 실제 약 $7이 든 선례(캐시 읽기 누락)가 있다. 아래 상단값은 이 과소추정 폭을 반영해 넓게 잡았다.

표본: 별도 시드로 F에서 5건. 짧은 기사·중앙값 근처·긴 기사가 섞이고 분야 묶음이 3개 이상이 되게 한다. 본 표본에서 뺀다. 같은 기사 2건은 한 번 더 돌려 실행 간 차이를 본다(총 7회 실행).

### 4.2 P4_DESIGN 지표·5% 목표와의 관계

| P4_DESIGN §4.2 지표 | 이 풀에 그대로 적용? | 이유와 대체 |
|---|---|---|
| 불필요 수정률(기사 단위) | 아니오 | 분모가 `expected.edit = none`(전문가 정답)이다. 이 풀에는 그 라벨이 없다. `p4_metrics.article_overedit`는 `expected_edit` 필드가 있어야 해 그대로 쓰지 않는다. R(수정안 제시율)을 내고 '불필요 수정률의 상한'이라고만 부른다 |
| 불필요 경고율(P군의 verify_first·경고) | 아니오 | P군은 보호가 타당하다고 판정된 시나리오다. 이 풀은 판정이 없다. W1·W2를 상한으로 낸다 |
| 경고 precision | 아니오 | 매칭할 gold가 없고 판독은 법률 판정이 아니다. §5 하한 진단치만 낸다 |
| 사실 추가율, 인용 정확도(ii) | 예 | 라벨 없이 판정된다(F1~F3). P4_DESIGN 정의와 같다. 단 이 풀은 test 분할이 아니므로 §7.1 출시 보류 규칙을 자동으로 발동하지 않고 사용자에게 보고한다 |
| 흐름·논조 보존 | 부분 | 기자 판정 지표다. 사용자 판정은 라벨에 반영하지 않으므로(2026-10-16) §5 진단 메모로만 다룬다 |
| 검토 지연·비용 | 예 | 같은 정의 |

LEGAL §4의 '유지가 타당한 표본의 과잉 경고율 5% 이하'(P4_DESIGN 204행에서 제안 목표로만 유지)는 분모가 '유지가 타당하다고 판정된 표본'이다. 이 풀은 그 판정이 없으므로 같은 정의로 적용할 수 없다. 쓸 수 있는 논리는 한 방향뿐이다. W2의 Wilson 상한이 5% 미만이면, 정당한 경고가 섞여 있더라도 이 모집단의 과잉 경고율도 5% 미만이다. W2가 5% 이상이면 그 자체로는 아무것도 말하지 않는다. 판독 하한(§5.4)과 함께 보고한다. 어느 경우에도 합격·불합격으로 쓰지 않는다. 어떤 별 단계를 '경고'로 볼지(★≥1·≥2·3)도 사용자가 정한다. 이 문서는 W2를 주 지표로 권고한다. ★1은 SKILL상 '확인 권고'이고 표에서 낮은 순위로 밀린다.

## 5. 판독 절차

### 5.1 판독 대상

- ★3 finding 전수.
- ★2 finding: ★≥2 finding이 120건 이하이면 전수, 넘으면 고정 시드 무작위 120건(포함 확률 역수로 가중).
- ★1 finding: 무작위 20건(서술용, 하한 계산에서 제외).
- F1~F3 플래그가 선 finding 전수(별과 무관).

### 5.2 코드북

판독 단위는 finding이다. 판독자는 기사 전문(또는 §8 결정 7에 따라 해당 문장과 앞뒤 문장)과 finding(구절·별·사유·수정안·설명)만 본다. 법적 결론을 내리지 않는다. 각 코드는 기사 안의 근거로 확인할 수 있어야 한다.

| 코드 | 이름 | 기준(하나라도 해당하고, 기사 안 근거를 지목할 수 있을 때) |
|---|---|---|
| A1 | 소재·논조만으로 경고 | 사유가 주제의 민감성, 공인·기관 비판, 부정적 평가어뿐이고 사실 적시와 연결되지 않는다(SKILL §3 '다음만으로는 경고하지 않는다') |
| A2 | 분쟁 이력 근거 | 사유가 인물·매체의 과거 분쟁 이력이다 |
| A3 | 기사 안에서 반박됨 | 단정이라고 지적한 구절의 근거(공식 자료·통계·발표·판결)가 같은 기사에 명시돼 있고 finding이 그것을 언급하지 않는다 |
| A4 | 없는 불일치 | 제목·본문 절차 단계, 수치·날짜·대상 불일치를 지적했는데 기사 안에서 일치한다 |
| A5 | 당사자 입장 반영됨 | `reply_opportunity_unknown`류 경고인데 기사에 해당 당사자의 입장·해명이 이미 있다 |
| A6 | 적용 범위 밖 기준 | 선거기간·기관이 맞지 않는 선거 심의기준, 기사와 무관한 경로를 근거로 경고한다 |
| B | 정당했을 수 있음 | 실제 기사 특징(제목이 본문보다 확정적, 출처 없는 단정, 사인 식별 단서, 모욕적 표현 등)을 가리키고, 해소 여부가 기사 밖 사실이나 법적 판단에 달렸다 |
| C | 판단 불가 | 법률 판단이 필요하거나 판독자가 근거를 찾지 못했다 |
| D | 도구 결함 | 구절이 기사에 없거나 다른 블록이다, finding 설명이 기사에 없는 내용을 전제한다, 반론 경로를 '허위·위법'으로 표현한다 |

수정안 표시(코드와 별개, 복수 가능): E1 사실 추가, E2 직접인용 변경, E3 핵심 논지·비판 강도 약화(공익 비판의 완곡화), E4 '의혹·논란' 덧붙이기만으로 해소 처리.

A는 좁게 쓴다. A 기준에 들지 않는 것은 모두 B 또는 C다. 'A가 아니다'는 '경고가 정당하다'는 뜻이 아니다.

### 5.3 판독 주체와 지위

- 1차 분류: DeepSeek v4-pro(로컬 DeepSeek 래퍼). 프로젝트 규칙상 분류는 DeepSeek 우선 대상이고, 호스트(Claude)와 다른 계열이라 자기 선호 편향이 줄어든다. 출력에 코드와 기사 안 근거 위치(블록·문장)를 요구하고, 위치 문자열은 코드로 원문 부분문자열 대조를 한다. 반출 게이트가 막으면 우회하지 않고 중단·보고한다.
- 교차 표본: 20건(코드 A·B·C·D가 고루 들게 층화)을 Opus 5.5가 DeepSeek 결과를 보지 않고 독립 분류한다. A 대 비A의 일치를 Cohen kappa와 Gwet AC1로 낸다. 일치가 낮으면 하한을 판독자별로 따로 내거나 '판독자 간 불일치로 하한 미산출'로 보고한다. 일치 기준값은 사용자가 정한다.
- 모든 판독 결과에 `label_source=llm_preliminary`를 붙인다(P4_DESIGN §10-7). 최종 사람 라벨을 붙일 평가자가 없으므로(법률 평가자 추가 확보 불가, 2026-10-16) 이 판독은 끝까지 진단치다.
- 사용자 진단 메모(§8 결정 5): 사용자는 기사 작성자라 이해관계가 있다. 메모는 별도 열(`reader=author_diagnostic`)로만 남기고 라벨·하한 계산·변호사 합의 라벨에 섞지 않는다.
- 변호사 검토 요청은 계획에 넣지 않는다(사용자 결정: 평가자 추가 확보 불가).

### 5.4 하한 진단치

L2 = (★≥2 finding 중 A로 분류된 것이 1건 이상인 기사, ★2 표본 가중 반영) / n. 판독자별로 따로 낸다. 보고 형식은 '과잉 경고율은 이 표본에서 [L2, W2] 범위로 추정되며, L2는 LLM 판독 진단치'다. D(도구 결함) 비율은 과잉 경고와 따로 보고한다.

### 6.3 저장·보관·로그

이 평가는 프로젝트 원칙 '기사 원문 기본 무보관, 로그 제거, 세션 TTL 30분'과 충돌한다. 입력 사본, 원본 stream-json(기사 전문과 passage 포함), 결과 JSON(span 원문 포함)이 디스크에 남기 때문이다. 예외의 근거와 범위:

- 근거: 대상이 미발행 원고가 아니라 사용자 본인이 쓰고 발행한 기사이고, 사용자가 외부 전송·재배포를 허용했다(2026-10-16). 이 원칙의 보호 대상(미발행 원고·취재원)과 성격이 다르다. 예외는 이 점검에만 적용하고 플러그인 기본 동작은 바꾸지 않는다.
- 위치: 모두 저장소 밖 `~/.local/share/press-dispute-review/eval/overwarn/<run_id>/` 아래(`input/`, `raw/`, `results/`, `reading/`). 저장소에는 집계만 둔다.
- 보관 기한: `raw/`는 추출과 파일럿 ③·⑤ 검증이 끝난 당일 삭제한다. `input/`은 본 실행과 판독이 끝나면 삭제한다(원본은 기사 풀에 있다). `results/`·`reading/`은 결과 보고서 확정 후 30일 보관하고 구절·수정안 문자열을 지운 집계 파일만 남긴다. 기한은 §8 결정 6에서 바꿀 수 있다.
- 세션 전사: `--no-session-persistence`로 남기지 않는다. 파일럿 ⑤에서 확인한다.
- 로그: MCP 서버 로그·Claude Code 캐시 디렉터리에 기사 문자열이 남는지 파일럿 ⑤의 부분문자열 검색으로 확인한다. 남으면 경로를 기록하고 실행 뒤 지운다.
- 학습·색인 재사용 금지: 이 기사들을 RAG 색인에 넣지 않는다. 미세조정에 쓰지 않는다.
- 용량: C: 여유가 작다. 원본 stream-json은 기사당 수백 KB로 추정(미측정)되어 바로 지운다. 결과 JSON은 기사당 수십 KB로 본다.

## 7. 선행 조건

1. **API 키 유효성(A1 경로).** `ANTHROPIC_API_KEY`가 있는지, 유효한지, 잔액이 있는지를 실행 전에 확인한다(전역 §3.1 F: 인증 전환 전 유효성 확인). 없으면 A2로 가되 crontab·전사 게이트를 필수로 둔다. 키는 실행기 하위 프로세스 환경에만 넣는다. 셸 프로필·settings에 넣지 않고 로그·결과에 쓰지 않는다. 대화형 Claude Code의 OAuth 인증을 바꾸지 않는다(인증 전환으로 OAuth 세션을 잃은 선례).
2. **MCP 서버와 활성 색인.** 대화형 세션의 MCP 서버 재시작은 사용자 몫으로 남아 있다(2026-10-16 상태). 배치 실행은 실행마다 서버를 새로 띄우므로 재시작과 무관할 수 있다. 어느 쪽이든 파일럿 기준 2(snapshot `idx-06c1c3649636e7a2` 확인)로 닫는다. `PRESS_REVIEW_PYTHON`이 엔진 의존성이 설치된 파이썬을 가리키는지도 같이 본다.
3. **기사 풀 수집 실패와 무관함.** `last_run.json`의 2026-10-12 실패는 그 뒤 신규 기사가 안 들어왔다는 뜻이다. 이 점검은 고정 시점의 frame manifest를 쓰므로 영향이 없다. 확인만 했고 고치지 않는다. 루트의 2026-10 파일 8건은 별도 경로로 들어온 것으로 보이며 경위는 확인하지 않았다.
4. **호스트 기록 방식.** P4_DESIGN §10-8 결정을 따른다. 결과 meta.host에 모델 ID(시작 메시지와 modelUsage), effort(플래그 값), Claude Code 버전, 스킬 파일 sha256, 플러그인 커밋, 지시문 sha256, 색인 snapshot을 쓴다. 모델 별칭(`sonnet`)이 아니라 전체 ID로 고정한다.
5. **구현.** 표본 추출기, 입력 정제·블록 JSON 생성기, 실행기, 추출기, 집계기, 누수 점검기가 필요하다. 모두 `evals/` 아래 새 스크립트로 두고 엔진은 바꾸지 않는다. 데이터 경로는 인자로 받는다.

## 8. 사용자 결정 항목

결정은 하나씩 받는다. 각 항목은 권고안 하나와 옵션, 득실이다.

1. **표본 크기.** 권고: n=100(+파일럿 5, 중첩 확장 가능). 득: W2가 10%면 구간 5.5~17.4%, 중대 실패 0건이면 상한 3.7%. 실: 분야별 추정은 거칠다. 옵션 n=30: 비용 1/3, 구간 폭 20~30%p라 경고율 크기 정도만 본다. 옵션 n=300: 구간 폭 5~9%p, 0건 상한 1.3%. 비용·판독량 3배.
2. **호스트 모델·effort.** 권고: Sonnet 5.5, effort high. 전제는 플러그인 README가 안내할 기본 설정과 같게 맞추는 것이다(README 안내는 미정). 득: 비용이 가장 낮고 일반 사용자 기본 모델일 가능성이 크다. 실: 더 강한 모델의 경고 양상은 모른다. 옵션 Opus 5.5 high: 비용 약 2배. 옵션 Fable 5.1: 약 5배, 사용자 기본 설정과 멀다. 옵션 두 설정 비교(30건 부분표본에 두 번째 모델): 모델 간 차이를 보나 비용이 늘고 결론이 둘로 갈린다.
3. **실행 경로.** (2026-10-17 사용자 결정: API 키 경로 불승인, 구독 경로로 파일럿 실행. 구독 경로의 통제는 `--restricted --tools Skill` + `ENABLE_CLAUDEAI_MCP_SERVERS=false`로 훅·전역 CLAUDE.md·사용자 플러그인·claude.ai 커넥터를 뺀 것을 확인했다. `docs/coverage/P4_overwarning_pilot.md` §1. 아래는 원 권고 기록.) 권고: A1 `claude -p --bare`(API 키). 득: 훅·전역 CLAUDE.md 혼입이 없고 구독 주간 풀을 쓰지 않는다. 실: 실제 달러가 나가고 키 확인이 선행된다. 옵션 A2 `claude -p` OAuth: 추가 과금이 없으나 주간 풀을 쓰고, 전역 규약이 호스트 맥락에 섞이며, autoresume 예약 누적 위험을 게이트로 막아야 한다. 옵션 D `claude plugin eval`: 도구가 정리돼 있으나 effort 고정이 안 되고 케이스 파일이 저장소 안에 놓인다.
4. **예산 상한.** 권고: 파일럿 상한은 7회 × 고른 모델의 기사당 상단값(§3.4: Sonnet $14, Opus $28, Fable $70). 본 실행 상한은 파일럿 실측 기사당 비용 × n × 1.5로 정하고, Sonnet·n=100이면 본 실행 한정 하드 상한 $200을 둔다(파일럿·판독 비용 별도, §9 총액과 다름). 기사당 `--max-budget-usd`는 실측 p90의 2배. 득: 실측으로 정하고 폭주를 막는다. 실: 파일럿 뒤 한 번 더 승인이 필요하다. 옵션: 고정 총액을 먼저 정하고 표본 크기를 거기에 맞춘다.
5. **사용자 진단 메모.** 권고: 쓰되 범위를 ★3 전수와 A로 분류된 finding으로 제한하고, 별도 열로만 남긴다. 득: LLM 판독의 명백한 오분류를 잡고 기자 관점의 흐름·논조 보존 신호를 얻는다. 실: 작성자 본인이라 편향이 있고 사용자 시간이 든다. 옵션 미사용: 하한이 LLM 판독만으로 나온다. 옵션 전수 판독: 시간이 많이 들고 이해관계 문제는 같다.
6. **결과 공개 범위와 로컬 보관 예외.** 로컬 보관(§6.3)은 프로젝트 '기사 원문 기본 무보관' 원칙의 예외이므로 이 결정에서 함께 승인받는다. 권고: 저장소에는 집계만, 구절·수정안·기사 ID는 로컬에 두고 30일 뒤 문자열을 지운다. 득: 업무상저작물 귀속·제3자 개인정보 미확인 문제를 피한다. 실: 외부 검토자가 사례를 볼 수 없다. 옵션: finding 구절과 수정안을 포함해 공개(사용자 진술 근거, 미확인 권리 항목은 남는다). 옵션: 집계도 비공개.
7. **입력 가명화와 판독 전송 범위.** 권고: 호스트 입력은 가명화하지 않는다(식별 가능성 판단이 플러그인의 핵심 검토 항목이고 이미 발행된 기사다). DeepSeek 판독에는 해당 문장과 앞뒤 1문장, finding만 보낸다. 득: 호스트 평가의 타당성을 지키고 추가 수신자에게 가는 개인정보를 줄인다. 실: 판독자가 기사 전체 맥락을 못 봐 A3(기사 안에서 반박됨) 판정이 약해진다. 옵션: 둘 다 기사 전문(판독 정확도 우선). 옵션: 사인 인명을 일관 가명으로 바꾼 사본을 호스트와 판독 모두에 사용(개인정보 최소화 우선, 식별성 판단 제한을 결과에 명시).
8. **주 지표의 별 단계.** 권고: W2(★≥2)를 주 지표로 하고 W1·W3을 함께 낸다. 득: ★1은 '확인 권고'라 경고로 세면 과대평가된다. 실: ★1 남발은 주 지표에 안 잡힌다(W1로 보완). 옵션: W1 주 지표.

## 10. 확인하지 못한 것과 후속

확인하지 못한 사실:
- `--bare`에서 `--plugin-dir` 플러그인의 `.mcp.json` 서버가 뜨는지, 도구 이름 접두가 SKILL `allowed-tools`와 같은지.
- `stream-json`에 `--verbose`가 필요한지, 결과 메시지에 `permission_denials`·`modelUsage`가 들어오는지.
- OAuth 경로에서 `--max-budget-usd`가 실제로 실행을 멈추는지.
- 실행마다 새로 뜬 MCP 서버가 활성 snapshot을 읽는지.
- 본문에 캡션·사진 설명 줄이 섞여 있는지, 끝 3줄 규칙이 서명을 빠짐없이 지우는지(이메일 1,303건 중 끝 3줄 밖 비율 미측정).
- 기사당 실제 비용·턴 수·검색 호출 수(선례 없음).
- 업무상저작물(저작권법 제9조) 귀속. 웹 확인을 하지 않았다.
- `rights_ledger.json` 빌드 코드가 새 최상위 키를 무시하는지.
- 브리프의 본문 길이 중앙값 약 1,535자의 측정 정의.

후속 항목(이번 범위 밖):
- [단독] 74건 추가 표본(경고 유발 표지가 많은 '어려운 음성' 성격).
- 300자 미만 13건·4,000자 이상 15건 전수 소규모 실행.
- 정정·반론·추후 표지 11건의 성격 확인(사용자).
- 결과에 따라 SKILL을 고치면, 중첩 확장분(아직 안 쓴 순열 구간)으로 재측정.
