# P3 색인 재빌드 실행 계획 (실행 전 계획 문서)

작성 2026-10-16. 이 문서는 계획이다. 재빌드·snapshot 승격·장부 쓰기는 하지 않았다. 근거 문서: docs/P3_DESIGN.md §1, docs/P4_DESIGN.md §5·§8.2·§10 결정 10, docs/STATUS.md, docs/coverage/P3_prefilter_*.md, docs/coverage/P2_remaining_sources_options.md, evals/README.md. 코드 확인 기준 커밋 `d06c4f3`.

이 문서의 수치는 아래 읽기 전용 확인에서 나왔다. 색인은 `immutable=1`, 장부는 `mode=ro`로 열었다. `build_index(dry_run=True)`를 장부 읽기 전용으로 1회 호출했다. 이 호출은 파일·포인터를 쓰지 않고 `od.mkdir`도 하기 전에 반환한다. 네트워크·DeepSeek·비밀 파일은 쓰지 않았다.

## 2. 실행 순서

기준선은 `evals/baselines/search_baseline_idx-34b8367d1dfe423d.json`(순위 변형 3개 포함, 질의 세트 해시 3개 기록)과 `search_pool20_idx-34b8367d1dfe423d.json`(풀링 20)에 이미 있다.

0. 사전 점검(읽기 전용). 모두 통과해야 진행한다.
   - 보존 사본 확인: `~/.local/share/press-dispute-review/baseline/corpus-idx-34b8367d1dfe423d.sqlite`(1,303,506,944바이트, 읽기 전용 파일)와 `index/` 안 원본의 sha256이 일치함을 이번에 확인했다(`8fa481dc…b7625f22`, 두 파일 동일).
   - 동시 실행 확인: `pgrep`에 수신·구조화 프로세스 없음(이번 확인 시점). 실행 직전 다시 본다. 판례 P-T3 수신은 2026-10-10 폐기·중단 상태다.
   - 테스트 기준: `PYTHONPATH=plugins/press-dispute-review/engine python3 -m pytest tests -q`(마지막 확인 1,173 passed·1 xfailed, 2026-10-10)를 구현 후 다시 돌린다.
1. ①·②·③·④ 구현과 단위 테스트(코드 변경은 이 계획 밖의 별도 작업). 색인 형식 `INDEX_FORMAT`을 `pdr-index-3`에서 올린다. snapshot 해시가 형식 문자열과 passage 정본에서 나오므로(corpus_sqlite.py build_index) 새 snapshot id가 보장된다. `get_passage`·`submit_report` 증거 검증(passage_id·url·locator 일치)과의 호환은 ①에서 따로 정한다(결정 2).
2. 기준선 재측정 1회(선택, 권고). 기준선의 지연 값은 `loop.sh lawT3`(판례 수신) 동시 실행 중에 쟀다고 기준선 JSON `env.note`에 적혀 있다. 지금은 수신이 없으므로 같은 하네스로 보존 사본에서 지연을 다시 재야 전후 지연 비교가 공정하다: `python evals/run_search_evals.py run --index <baseline 사본> --latency`. 라벨 없는 지표·순위는 같은 색인·같은 코드이므로 변하지 않아야 한다.
3. 빌드. 현행 `build_index`는 빌드가 끝나면 `CURRENT` 포인터를 바로 새 파일로 바꾼다(`_write_pointer` 후 `_prune`). 즉 승격이 빌드에 붙어 있다. 되돌릴 수 있게 하려면 기본 경로에 쓰지 말고 `build_index(manifest, <임시 out_dir>)`를 파이썬으로 호출해 별도 폴더에 만든다(어댑터 CLI `python -m press_review.ingestion build_index`는 출력 폴더를 고정(`<data>/index/`)하고 `--out-dir` 인자가 없다). 이 방식과 대안은 결정 4.
4. 전후 측정: 같은 질의 세트(`regression_v0.json`·`gold_auto_dev.json`·`latency_load.json`, 해시 `98bb9d4b049c2a2f`·`662e3c61b99d2586`·`fbca7e622cbd10b3`)·같은 자동 gold(Q1·Q2·Q6 금지 사건·Q7)로 `run_search_evals.py run --index <새 색인> --latency`와 `--pool 20`을 돌린다. 지연은 질의마다 예열 3회 버림·20회 측정·중앙값과 p95(기준선 방법과 동일). 사건 단위 등급(E4)은 아직 없어 Recall@10·nDCG@10은 못 낸다(P4 후속).
5. 전후 비교표(아래 승격 기준 표)를 만든다. 질의별 짝 차이와 라벨 없는 지표(상위 10 안 목록 장 수, 권위 유형 분포, 같은 본문 중복 수, 질의당 연구 passage 수, date_unknown 비율, 0건 질의 수, Q6 금지 사건 등장 수)를 낸다.
6. 승격 판단은 사용자(결정 5). 승격 방법은 `index/CURRENT`에 새 파일명을 한 줄 쓰는 것이고 되돌리기는 이전 파일명으로 되쓰는 것이다(`open_current`가 포인터를 읽는다).

## 4. 위험·중단 조건·롤백

- 위험 1: 승격이 빌드에 붙어 있다(`_write_pointer`). 기본 경로에 그대로 빌드하면 비교 전에 MCP·검토 경로가 새 색인을 쓴다. 대응: 3단계의 별도 out_dir 빌드(결정 4).
- 위험 2: ①로 passage_id가 바뀌어(제거된 쪽 id) 기존 보고서·평가 시나리오의 `evidence`·`evidence_links`가 깨질 수 있다. 사건 단위 gold는 영향이 적으나 `p3_scenarios.json`의 `passage_id` 연결과 로컬 골든은 passage_id를 쓴다. 대응: 시나리오 연결 passage가 새 색인에 있는지 `run_p3_evals.py`로 점검(없으면 `pending_corpus`)하고, 제거 id를 남은 id로 잇는 별칭 표 여부를 결정 2에서 정한다.
- 위험 3: ③에서 형태소 분석 결과가 trigram 부분일치(정확 구문 일치)보다 재현율을 낮출 수 있다. 대응: trigram 색인은 유지하고 형태소 층은 추가 신호로 두는 설계 후보를 구현 시 검토. 표 2절의 Q1·Q2·0건 질의 기준이 감시한다.
- 위험 4: 권위 가중 판례 1.10 > 사례 1.01 > 연구 1.0은 ①~④ 후에도 그대로이므로 순위 상수 변화와 색인 변화가 섞이지 않는다(상수는 건드리지 않는다).
- 중단 조건(하나라도 해당하면 승격하지 않고 보고한다): 승격 기준 표의 Q1·Q2·Q7·시점 필터 중 하나라도 하락, 새 snapshot passage 수가 예상 산식과 안 맞음, `ledger changed during the build` 오류, 테스트 실패, 빌드가 `--max-seconds` 시간 상한(`check_time`)에 걸림(부분 색인은 발행되지 않는다).
- 롤백: 기본 경로에서 승격했다면 `index/CURRENT`를 `corpus-idx-34b8367d1dfe423d.sqlite`로 되쓴다(원본이 `KEEP_INDEXES=3` 안에 남아 있는 동안). 원본이 지워졌어도 `baseline/` 사본(sha256 일치)을 `index/`에 복사하고 포인터를 쓰면 된다. 별도 out_dir 빌드는 포인터를 바꾸지 않았으므로 새 파일을 지우면 끝이다. 장부는 읽기만 하므로 롤백 대상이 아니다.

## 5. 사용자 결정이 필요한 항목

1. 시정권고 현황(pac_board_correction_status)을 재빌드 전에 처리할지. 현재는 표본 12개만 구조화·`--apply` 미실행이라 색인에는 표본 사건 152건 규모만 있다(P2_remaining_sources_options 표). 권고: 이번 재빌드와 분리해 지금 상태로 포함하고, 전량 구조화·admission(추정 비용 $6.05~6.42, 같은 문서 추정)은 별도 결정으로 미룬다(재빌드를 두 번 하지 않으려면 먼저 하고 묶는 안도 가능). 옵션: (가) 현 상태로 재빌드 (나) 전량 구조화·`admission --apply` 후 재빌드(DeepSeek 비용 발생) (다) 소스를 색인에서 제외.
2. ① 중복 제거의 규칙: 어느 쪽 passage_id를 남기고, 제거된 id를 별칭으로 남길지. 권고: 정본 첨부(전체본 우선이 아니라 가장 먼저 장부에 들어온 chunk_id 하나)를 남기고, 제거된 chunk_id와 locator를 별칭 표에 보존해 `get_passage`가 옛 id도 해석하게 한다. 옵션: (가) 별칭 보존(증거 호환 유지, 구현 큼) (나) 단순 제거(작음, 옛 id는 없어짐 → 평가 시나리오 재연결 필요) (다) 제거하지 않고 중복 표시 열만 추가해 검색 단계에서 접기.
3. ③ 형태소 분석기의 선택과 의존성. 권고: 이번 재빌드에서는 ③·④를 제외하고 ①·②만 하며, 형태소 분석은 라이선스·설치·플러그인 배포 영향을 조사한 뒤 별도 빌드로 넣는다. 이유: 지금 저장소에 분석기 의존성이 없고 플러그인 사용자가 설치해야 하며 지연·빌드 시간 영향이 미측정이다(P4 결정 10은 한 번에 빌드로 정했으므로 이 권고는 그 결정의 예외 요청이다). 옵션: (가) ①~④ 한 번에(결정 10 유지, 의존성 결정 선행 필요) (나) ①·②·⑤만 지금, ③·④는 다음(효과 분리 가능, 빌드 2회) (다) 의존성 없는 규칙 기반 조사 층(사전 없는 어말 처리)만 ④로 구현.
4. 빌드와 승격의 분리 방식. 권고: 파이썬으로 `build_index`를 별도 out_dir에 호출해 만들고 비교 통과 뒤 사용자 승인으로 `CURRENT`를 바꾼다. 옵션: (가) 기본 경로에 빌드(포인터가 바로 바뀜, 롤백은 포인터 되쓰기) (나) `build_index`에 `--no-promote` 같은 인자를 추가(코드 변경, 이후 재빌드에 재사용 가능).
5. 승격 기준의 수치 임계와 지연 상한. 권고: 2절 표의 조건을 그대로 쓰고 지연은 P4_DESIGN §5.5 절차(pilot의 기사당 검색 호출 수 × p95)로 정하며, 그전에는 '기준선 대비 2배 이내'처럼 임시값을 쓰지 않고 지연은 보고만 한다. 옵션: (가) 위 권고 (나) 임시 상한을 지금 정한다(예: 기준선 p95의 N배, 근거 없음).
6. 재빌드 시점. 권고: 지연 재측정(2단계)과 결정 1~4가 끝난 뒤. 옵션: P4 설문 응답 처리와 병행 가능(색인 변경이 시나리오 gold에 영향을 주지만 passage_id 연결은 위험 2로 점검).

## 6. 확정하지 못한 항목

- `chunks.text_sha256` 열이 실제로 채워져 있는지(①의 키로 바로 쓸 수 있는지).
- 사건 없이 쪽 단위 chunk만 있는 첨부가 admission 제외 필터(`r["case_id"]` 조건)를 빠져나가는지, 현재 데이터에서 해당 건수.
- 빌드 시간·디스크의 ③ 도입 후 값, 테스트 소요 시간(미측정).
- 기준선 지연이 수신 프로세스 동시 실행 조건이라는 점의 영향 크기(2단계 재측정으로 확인).
- 가중·강등 로직이 ②의 열 기반 교체 후 같은 결과를 내는지(구현 후 비교로만 확인 가능).
