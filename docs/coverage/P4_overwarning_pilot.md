# P4 과잉 경고 점검 파일럿(구독 경로, 5건)

실행 2026-10-17. 설계: `docs/P4_OVERWARNING_DESIGN.md`. 사용자 결정(2026-10-17): API 키 경로는 쓰지 않는다. 구독(OAuth) `claude -p`로 파일럿 5건만 돌리고, 다음 규모와 effort는 실측 뒤 다시 정한다.

이 문서는 하네스 검증과 비용 실측 기록이다. 경고율 추정이 아니다. 5건으로는 경고율을 말할 수 없다(0/5의 95% Wilson 상한 43.4%). 결과는 법적 안전성을 뜻하지 않는다. 기사 본문·제목·구절은 이 문서에 옮기지 않았다.

## 1. 구독 경로의 호스트 통제

### 1.1 확인한 방법

설계서가 지적한 문제는 세 가지였다. 전역 훅이 재개 예약(crontab)을 거는 것, 전역 `~/.claude/CLAUDE.md`가 호스트 맥락에 섞이는 것, 세션 전사가 남는 것이다. Claude Code 2.1.301의 도움말에서 후보를 찾아 Haiku 탐침(도구 없음, 1턴)으로 먼저 시험했다.

| 탐침 | 결과 | 판정 |
|---|---|---|
| `--safe-mode --plugin-dir …` | 플러그인은 목록에 있으나 MCP 서버 0개, 스킬 해석 안 됨 | 사용 불가 |
| `--restricted --plugin-dir …` | press-review MCP 연결, review 스킬 해석. 사용자 설정 파일을 읽지 않아 사용자 훅과 사용자 플러그인이 빠진다. 단 claude.ai 커넥터(Drive·Docs 등)와 WebSearch가 남는다 | 보완 필요 |
| 양성 대조: `--setting-sources project`, 작업 폴더에 표식 문자열을 넣은 CLAUDE.md | 표식 YES, 전역 CLAUDE.md 고유 어휘 YES. 맥락 51,650토큰 | 탐침이 CLAUDE.md 혼입을 감지할 수 있음을 확인 |
| `--restricted --tools Skill` + 환경변수 `ENABLE_CLAUDEAI_MCP_SERVERS=false`, 같은 표식 폴더 | 표식 NO, 전역 어휘 NO. 맥락 11,143토큰. 도구는 Skill과 press-review 5개뿐, MCP 서버는 press-review 하나 | **채택** |

채택 구성(실행기 `run_one.sh`, 로컬 전용):

```
ENABLE_CLAUDEAI_MCP_SERVERS=false PRESS_DISPUTE_DATA_DIR=~/.local/share/press-dispute-review \
timeout 900 claude -p "<고정 지시문 + article JSON>" --restricted --tools Skill \
  --plugin-dir <저장소>/plugins/press-check \
  --model claude-sonnet-5-5 --effort high \
  --output-format stream-json --verbose --no-session-persistence \
  --permission-mode dontAsk \
  --allowed-tools "Skill <press-review>__corpus_status <…>__prepare_article <…>__search_cases <…>__submit_report" \
  --max-budget-usd 3
```

- 작업 폴더는 저장소 밖 `~/.local/share/press-dispute-review/eval/overwarn_pilot/work/`다.
- 고정 지시문(sha256 앞 16자리 `1af262d4ff5ec9b1`)에는 스킬 호출, `article` 인자로 넘기라는 것, 발행일, 블록 확인 없이 진행하라는 것만 넣었다. 분쟁 이력과 평가 목적은 알리지 않았다.
- `--max-turns`는 도움말에 없다. 기사당 상한은 `--max-budget-usd 3`과 `timeout 900`으로 걸었다. 구독 경로에서 `--max-budget-usd`가 실제로 멈추는지는 확인하지 못했다. 이번 실행은 기사당 $0.43 이하라 상한에 닿지 않았다.
- 합성 검증 1회에서 호스트가 `corpus_status`를 불렀고 dontAsk라 거부됐다. 읽기 전용 상태 조회라 실제 기사 실행 전에 허용 목록에 넣었다. 이 도구는 SKILL `allowed-tools` 머리말에는 없다(후속 항목).

## 2. 표본과 입력 준비

- 틀: 설계서 §2.1 주 표본 틀 3,333건(정정·반론 표지, 300자 미만, 4,000자 이상 제외). 본문 길이 p25 954자, 중앙값 1,285자.
- 추출: 시드 `overwarn-pilot-v1`. 상위 분야 묶음 5개(정치부·경제정책·부동산·사회부·금융)를 시드로 섞어 묶음마다 1건씩 뽑았다. 길이는 2건을 300~953자, 3건을 954~1,285자에서 뽑았다. 중앙값 이하로 제한한 이유는 비용 절감이다. 그래서 이 파일럿의 비용은 표본 전체보다 낮게 나온다(§4에서 보정).
- 뽑힌 5건: 본문 834~1,090자, 발행 연도 2019·2020·2024·2025·2026, 블록 8~13개, 부제 0~2개.
- 정제: 설계서의 '끝 3줄' 규칙만으로는 서명이 지워지지 않았다. 이 아카이브의 상당수 기사는 끝에 포털 홍보 줄(▶로 시작)이 붙어 있고 서명 줄은 그 위에 있다. 규칙을 '끝부분의 ▶ 홍보 줄을 먼저 떼고, 남은 끝 3개 비공백 줄에서 이메일과 이름+기자 서명을 지운다'로 고쳤다. 모집단 3,372건 중 ▶ 줄이 있는 기사 1,329건, 이 규칙으로 서명이 잡히는 기사 1,096건이다. 파일럿 5건 중 2건에서 홍보 줄 2·3개와 서명 줄을 지웠다(84·96자). 정제 뒤 입력 5건에 '@'는 0건이다. 그 밖의 본문은 바꾸지 않았다.
- 블록: 헤더 title·subtitles와 빈 줄로 나눈 본문 문단으로 article.schema JSON을 만들었다. `context.genre`는 `unknown`이다.

## 3. 결과(건수만)

| 항목 | 합성 F01(참고) | 실제 5건 |
|---|---|---|
| overall_status | findings | 5건 모두 `no_actionable_findings` |
| finding | 1건, ★2, replace, 경로 correction·civil·follow_up, 근거 2건 | 0건 |
| ★≥1 / ★≥2 / ★3 기사 | — | 0/5, 0/5, 0/5 |
| 도구 호출 순서 | prepare → corpus_status(거부) → search ×2 → submit | prepare → corpus_status → search 0~4회 → submit. 2건은 검색 없이 제출, 1건은 prepare를 2번 호출(둘 다 성공, 원인 미확인) |
| 중대 실패 자동 점검 | G2·G3·G4 통과, 사실 추가 어휘 0 | finding이 없어 수정안 점검 대상이 없다. G2·G3·G4 통과, 설명문 사실 추가 어휘 0 |

해석:
- 스킬은 6회 모두 끝까지 작동했다. finding이 있는 경로(검색 → 수정안 → 제출 → 표)는 합성 기사로만 확인했다. 실제 기사에서 finding이 나온 사례는 없다.
- 실제 5건이 모두 '경고 없음'이었다. 이것이 과잉 경고가 적다는 증거는 아니다. n=5이고, 중앙값 이하 길이만 뽑았으며, 한 기자의 기사다. 반대로 2건은 반대·면책 검색 없이 '경고 없음'으로 끝났다. SKILL은 후보가 있을 때만 검색을 요구하므로 규칙 위반은 아니다. 하지만 후보 선별 단계에서 놓친 것이 있는지는 이 자료로 알 수 없다(recall은 이 점검의 범위 밖이다).
- `no_actionable_findings`는 안전 보장이 아니다(SKILL §11).

### 4.2 규모·effort별 재추정(설계서 §3.4 대체)

전제: 표본 전체는 파일럿보다 길고(중앙값 1,285자, p75 1,650자) finding이 있는 기사가 섞인다. 기사당 환산 비용을 하단 $0.16(실측 최소), 중심 $0.30~0.45(길이·finding 가산), 상단 $0.80(실측 최대의 약 2배)으로 잡았다. medium 수치는 측정하지 않았다. 출력·사고 토큰이 비용의 약 20%라 절감 폭이 작다고 보고 high의 0.75~0.9배로 추정했다. medium으로 바꾸면 검색 횟수가 줄 수도 있으나 확인하지 않았다.

| 규모 | high 중심 | high 범위 | medium 중심(추정) | 파일럿 실제 5건 대비 한도 소모 |
|---|---|---|---|---|
| n=30 | $9~14 | $5~24 | $7~12 | 약 7~10배 |
| n=50 | $15~23 | $8~40 | $11~20 | 약 11~17배 |
| n=100 | $30~45 | $16~80 | $23~41 | 약 23~34배 |

- 설계서 §3.4의 Sonnet n=100 추정 '$50~100(상단 $200)'은 이 표로 바꾼다. 실측 기반 중심값은 약 절반이다. 판독 비용(DeepSeek·Opus 교차 표본)은 별도다.
- 구독 한도 관점에서는 이 표의 환산액이 절대 청구액이 아니다. 소모 비율만 상대 비교에 쓴다. 이 세션에서 주간 사용량(`/usage`)을 읽지 못했다. 다음 실행 전후로 사용자가 `/usage`를 보면 '실제 5건 = 주간 한도의 몇 %'를 얻을 수 있고, 위 배수를 곱해 규모별 소모율을 바로 계산할 수 있다.
- 시간: 기사당 28~58초(순차). n=100이면 순차 약 1~1.5시간이다.

## 5. 데이터 처리

- 입력·원본 stream-json·결과 JSON은 모두 `~/.local/share/press-dispute-review/eval/overwarn_pilot/` 아래에만 있다(약 1.6MB). 저장소에는 이 문서만 커밋했다.
- 원본 stream-json(raw/)은 추출과 위 검증을 마친 뒤 삭제했다. 결과 JSON에는 제출 내용, 검색 질의, 사용량이 남아 있다.
- 외부 전송은 `claude -p` 호스트 호출(Anthropic)뿐이다. DeepSeek·웹 검색은 쓰지 않았다.
- 로컬 보관 자체가 프로젝트 '기사 원문 기본 무보관' 원칙의 예외다. 설계서 §8 결정 6에서 사용자 승인이 필요하다.

## 6. 한계와 후속

- n=5, 중앙값 이하 길이, 0건 경고. 경고율·분야 차이·별 분포에 대해 말할 수 없다.
- 실제 기사에서 finding 경로(수정안 점검 G2·G3·사실 추가)를 아직 검증하지 못했다.
- 반복 실행을 하지 않았다(사용자 지시로 생략). 실행 간 변동은 모른다.
- 통제 환경(`--restricted`, CLAUDE.md·사용자 플러그인 없음)은 실제 사용자 환경과 다르다. 의도한 차이다. 결과는 '깨끗한 호스트 + 스킬' 조건의 값이다.
- `--restricted`가 전역 CLAUDE.md를 빼는 것은 표식 탐침(Haiku)과 맥락 토큰 차이로 확인했다. 본 실행(Sonnet)의 맥락을 직접 덤프해 확인하지는 않았다.
- 후속(이번에 고치지 않음): SKILL `allowed-tools`에 `corpus_status`가 없다. 호스트가 매번 부르므로 일반 사용자 세션에서는 권한 확인이 뜰 수 있다. 1건에서 prepare_article이 2번 호출된 원인은 확인하지 않았다.
- 설계서 §3.5의 crontab 게이트 정의를 '오케스트레이터 자신의 재개 예약을 뺀 차이 0'으로 고쳐야 한다(이번 판정은 이 정의로 했다).
