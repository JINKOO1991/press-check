# press-check 처음 쓰는 분을 위한 안내

이 문서는 Claude Code는 설치했지만 GitHub, 플러그인, 터미널 같은 말이 낯선 기자와 데스크를 위한 안내입니다. 설치부터 첫 검토까지 순서대로 따라 하면 됩니다.

## 1. 이 도구가 하는 일, 하지 않는 일

- 기사 원고(제목·부제·본문·사진 설명)에서 언론분쟁 쟁점이 될 수 있는 표현을 찾고, 기사 취지를 유지하는 최소 수정안을 제안합니다.
- 편집 보조 도구이며 법률 자문이 아닙니다. 최종 게재 판단은 기자와 편집 책임자가 합니다.
- 별(★)은 분쟁이나 패소 확률이 아니라 검토 우선순위입니다.
- 근거를 찾지 못했다는 것이 "안전하다"는 뜻은 아닙니다.
- 원고 파일을 고치거나 발행하거나 외부에 보내지 않습니다. 검토 뒤 수정안을 반영한 변경본을 대화 화면에 보여 주지만 원본은 그대로 둡니다.

## 2. 먼저 알아 둘 용어

| 용어 | 기자가 알아야 할 만큼만 |
|---|---|
| GitHub | 프로그램 파일을 올려 두고 내려받는 인터넷 서비스입니다. 이 도구의 파일이 여기에 있습니다. |
| 플러그인 | Claude Code에 기능을 덧붙이는 추가 프로그램입니다. 스마트폰의 앱과 비슷합니다. |
| 마켓플레이스 | 플러그인 목록을 모아 둔 곳입니다. 앱스토어에 해당하며, 먼저 목록을 등록해야 플러그인을 설치할 수 있습니다. |
| MCP 서버 | 플러그인 안에서 Claude Code와 함께 돌아가는 작은 프로그램입니다. 이 도구에서는 원문 위치, 근거 인용, 수정안을 검사합니다. |
| 스킬 | 특정 일을 하는 명령 모음입니다. 이 도구는 `draft`, `review`, `explain`, `corpus-status` 네 가지를 제공합니다. |
| 터미널 | 글자로 명령을 입력하는 창입니다. 이 안내의 설치 단계는 Claude Code 입력창에서 하므로 터미널을 따로 열 필요는 없습니다. |

## 3. 설치

Claude Code를 연 상태에서 아래 순서대로 입력합니다. 입력 후 Enter를 누릅니다.

1. 마켓플레이스를 등록합니다.

```text
/plugin marketplace add JINKOO1991/press-check
```

2. 플러그인을 설치합니다.

```text
/plugin install press-check@press-check
```

3. 설치 범위를 고르는 화면이 나오면 "Install for you (user scope)"(나에게만 설치, 사용자 범위)를 선택합니다.

4. 플러그인을 다시 불러옵니다.

```text
/reload-plugins
```

5. 설치가 되었는지 확인합니다.

```text
/mcp
```

목록에 `plugin:press-check:press-review`가 보이고 6 tools(도구 6개)로 표시되면 정상입니다.

### 막혔을 때

| 증상 | 원인과 대처 |
|---|---|
| `Marketplace "press-check" not found` (마켓플레이스 "press-check"를 찾을 수 없음) | 1번을 건너뛰고 2번만 입력한 경우입니다. 1번의 `/plugin marketplace add JINKOO1991/press-check`를 먼저 입력한 뒤 2번을 다시 입력합니다. |
| 설치 범위를 고르는 화면에서 무엇을 골라야 할지 모르겠음 | "Install for you (user scope)"를 고릅니다. 이 선택으로 검증했습니다. |
| `/mcp` 목록에 `plugin:press-check:press-review`가 보이지 않음 | `/reload-plugins`를 입력한 뒤 `/mcp`를 다시 확인합니다. 그래도 없으면 Claude Code를 닫았다가 다시 엽니다. `/plugin`의 Errors 탭에 오류가 있는지도 봅니다. |

Windows에서는 Python 실행 파일 경로를 `PRESS_REVIEW_PYTHON` 환경변수에 지정해야 할 수 있습니다. 자세한 방법은 `plugins/press-check/README.md`의 요구사항 절을 참고하세요. 이 안내는 Windows에서 직접 확인하지 않았습니다. [확인 필요: Windows 설치 절차 미검증]

이 도구의 서버는 Python으로 실행되므로 컴퓨터에 Python이 있어야 합니다. 개발진은 Python 3.12에서 확인했고 다른 버전은 시험하지 않았습니다.

## 4. 처음 써 보기

### 먼저 알아 둘 점

이 저장소에는 실제 판례·심의 자료가 들어 있지 않습니다. 근거를 찾는 로컬 색인이 컴퓨터에 없으면, 검토를 요청해도 근거 검색 단계에서 오류가 납니다. 색인은 사용자가 직접 만들어야 하며, 방법은 `plugins/press-check/README.md`의 "코퍼스 만들기"에 있습니다. 이 과정은 터미널 명령이 필요해 기자가 혼자 하기에는 어려울 수 있습니다. [확인 필요: 비개발자용 색인 만들기 절차는 따로 검증되지 않음]

색인 없이 기능만 시험해 보려면 `PRESS_REVIEW_ALLOW_SYNTHETIC=1`을 설정할 수 있습니다. 이때의 근거는 시험용 가짜 자료이므로 인용하거나 법적 판단에 쓰면 안 됩니다.

### 검토 요청

1. Claude Code 입력창에 기사 원고를 붙여 넣습니다.
2. 이어서 "검토해 줘"라고 입력합니다.
3. `press-check:review` 스킬이 작동합니다. 먼저 원고를 제목·부제·본문·사진 설명으로 나눈 목록을 보여 줍니다.
4. 나눈 결과가 틀렸으면 바로 알려 주세요. 이 구분은 자동 추정입니다.
5. 잠시 뒤 결과 표가 나옵니다.

원고 파일을 쓰려면 `/press-check:review 파일경로`처럼 입력해도 됩니다.

### 가상 예시

아래는 설명을 위해 만든 가상 기사입니다. 실제 인물·기관과 관계가 없습니다.

> 제목: A시 시설관리공단 B 이사장, 공사비 빼돌렸다
>
> 본문: A시 감사위원회는 시설관리공단 공사 계약 일부에서 비용 처리가 부적정했다는 감사 결과를 공개했다. 감사위는 B 이사장 결재 건을 포함해 계약 3건을 수사 의뢰할 방침이라고 밝혔다. B 이사장은 취재진 질문에 답하지 않았다.

### 결과 표의 모양

아래 표는 이해를 돕기 위한 예시이며, 실제 출력의 문구와 건수는 다를 수 있습니다.

| 문제 요소 | 검토 필요도 | 사유 | 추천 수정안 |
|---|---|---|---|
| 제목 "공사비 빼돌렸다" (제목) | ★★★ | 본문은 수사 의뢰 방침 단계인데 제목은 범행을 확정한 것으로 읽힙니다. | 본문이 밝힌 사실 범위에 맞춘 문구로 최소 수정 |
| "답하지 않았다" (본문) | ★ | 실제로 반론을 요청했는지 원고만으로는 알 수 없습니다. | 발행 전 확인: 당사자에게 반론을 요청했는지, 응답이 있었는지 |

### 표 읽는 법

| 열 | 내용 |
|---|---|
| 문제 요소 | 원고에서 문제가 될 수 있는 구절과 그 위치 |
| 검토 필요도 | 별 1~3개. 아래에서 설명합니다. |
| 사유 | 왜 문제가 될 수 있는지 한 문장 |
| 추천 수정안 | 기사 취지를 유지하는 최소 수정. 원고만으로 고칠 수 없으면 "발행 전 확인: …"으로 확인할 내용을 적습니다. |

| 별 | 의미 |
|---|---|
| ★ | 확인 권고 |
| ★★ | 수정·보강 검토 |
| ★★★ | 발행 전 집중 검토 |

- 별은 검토 우선순위입니다. 분쟁이 생길 확률이나 질 확률이 아닙니다.
- 첫 화면에는 검토 필요도가 높은 순으로 5건까지 보입니다. 나머지는 건수로 알려 주며, 요청하면 더 볼 수 있습니다.
- 근거를 찾지 못한 항목은 "근거 미확보"로 표시됩니다.

### 변경본

검토 표 뒤에 변경본이 이어서 나옵니다. 수정안을 원고에 반영한 문안을 대화 화면에 보여 주는 것입니다.

- 변경본에는 ★2 이상이고, 발행 전 확인이 먼저인 항목이 아니며, 서버 검사에 걸린 이슈가 없는 수정안만 반영합니다. 나머지는 적용하지 않고 제안으로만 표시합니다.
- 미해결 확인 항목이 있으면 변경본 맨 위에 건수가 적힙니다.
- 원본 파일은 바꾸지 않습니다. 파일로 저장하려면 요청하세요. 원본 이름에 `.변경본`을 붙인 새 이름으로 저장하며 원본을 덮어쓰지 않습니다.
- 변경본은 제안입니다. 기자가 확인한 뒤 쓰세요. 서버 검사는 의미 보존이나 법적 안전을 보증하지 않습니다.
- 보도자료로 기사 초안을 만들려면 `/press-check:draft 파일경로`를 입력합니다. 출처를 귀속한 초안을 쓰고 바로 검토한 뒤 변경본까지 보여 줍니다.

### 항목별 자세한 설명

표에서 궁금한 항목이 있으면 아래처럼 입력합니다.

```text
/press-check:explain <report_id> <finding_id>
```

`<report_id>`와 `<finding_id>`는 결과 표에 함께 나오는 번호로 바꿔 넣습니다. 그냥 "두 번째 항목 자세히 설명해 줘"라고 말해도 됩니다.

상세 설명은 검토 후 30분 안에만 볼 수 있습니다. 시간이 지났으면 원고를 다시 붙여 넣고 검토를 새로 요청합니다.

### 자료 상태 확인

어떤 자료를 근거로 삼았는지 보려면 "코퍼스 상태 보여 줘"라고 말하거나 `press-check:corpus-status` 스킬을 씁니다. 자료 건수, 기준일, 시험용 가짜 자료 여부가 표시됩니다.

## 5. 개인정보·보안 안내

- 원고를 붙여 넣으면 Claude Code가 쓰는 호스트 모델의 제공자에게 전송될 수 있습니다. 기사 분석을 호스트 모델이 하기 때문입니다.
- 이 도구의 로컬 서버만으로 원고가 외부로 나가지 않는다고 장담할 수 없습니다. 서버는 원고를 블록으로 나누고, 근거를 검색하고, 위치와 수정안을 검사하는 일만 합니다.
- 이 플러그인은 원고를 호스트 모델 외의 다른 외부 제공자로 보내지 않습니다. 근거 검색은 컴퓨터 안의 색인에서만 하며 웹 검색을 하지 않습니다.
- 미공개 취재원이나 개인정보가 든 원고는 쓰기 전에 소속 매체의 정책을 먼저 확인하세요. 사내 정책상 외부 전송이 금지된 원고는 이 도구에 넣지 마세요.
- 취재원 실명, 연락처, 미공개 증거는 넣지 않는 것을 권합니다. 비식별 요약이나 문제 구절만으로도 누구인지 알아낼 수 있습니다.
- 원고, 검토 결과, 변경본은 디스크에 저장하지 않고 서버 메모리에 30분만 보관합니다. 30분이 지나거나 Claude Code를 다시 시작하면 지워지며, 상세 설명이나 변경본을 다시 보려면 원고를 다시 받아야 합니다.
- 서버 로그에는 요청 번호, 해시, 건수만 남기도록 설계했고 원고 문장은 기록하지 않습니다. 다만 Claude Code 자체의 대화 기록 보관은 Claude Code 설정을 따릅니다.
- 사진 자체는 판독하지 않고 사진 설명 글만 검토합니다.

## 6. 자료(코퍼스)와 이용 권리

- 검토 근거는 사용자 컴퓨터의 로컬 색인에서 찾습니다.
- 이 저장소에는 판례, 언론중재위원회 조정, 심의 자료의 원문이 들어 있지 않습니다. 들어 있는 것은 기능 시험용 가짜(합성) 자료뿐입니다. 실제 자료는 사용자가 수집 도구로 컴퓨터에 직접 만듭니다.
- 각 기관 자료의 이용 조건과 권리 표시는 사용자가 직접 확인하고 `rights set` 명령으로 기록해야 합니다. 이 기록은 법률 판단이 아니라 사용자의 기록이며 책임도 사용자에게 있습니다.
- 판례와 헌법재판소 결정은 법제처 이용안내 또는 공공데이터포털의 출처표시(제1유형) 표시에 따라 재배포가 허용되고, 조건은 출처 표기입니다(작성자 권리 장부 기록, 2026-11-06). 이 자료를 근거로 쓰면 "법원 판결, 법제처 국가법령정보센터 제공", "헌법재판소 결정, 법제처 국가법령정보센터 제공", "헌법재판소 결정, 헌법재판소 제공" 중 해당하는 문구가 함께 나옵니다. 기사에 옮길 때도 이 문구를 출처로 적으세요.
- 언론중재위원회와 인터넷선거보도심의위원회 자료는 이용 허락을 문의 중입니다. 2026-10-17에 문의했고 회신이 없어 2026-11-06에 국민신문고로 다시 질의했습니다. 이 자료의 코퍼스는 저장소에 포함하지 않습니다.
- 현재 저장소에는 어떤 코퍼스도 들어 있지 않습니다. 설치만으로는 근거 자료가 없고, 사용자가 색인을 만든 범위에서만 근거가 검색됩니다. 신규 설치의 권리 기본값은 모두 "알 수 없음(unknown)"이며, 허용은 사용자가 기록한 결정만 장부에 남습니다.
- 검색 결과를 기사에 옮길 때의 인용 범위와 출처 표시는 이용자가 판단합니다. 재배포 허락이 없는 소스는 화면 인용이 300자 이내로 잘립니다. 조문과 표시 동작의 대응은 `docs/CITATION_RULES.md`에 있으며 법률 판단이 아닙니다.
- 색인된 근거 자료의 규모는 사건 전체의 범위가 아닙니다. 권리 보류, 비공개, 추출 제외 자료가 있고, 최근 대법원 판례는 보강이 부족합니다. 자료 기준일도 따로 확인하세요.
- 사건번호와 인용문은 서버가 자료와 일치하는지 검사하지만, "이 기사 구절에 그 기준이 적용되는가"는 호스트 모델의 판단입니다. 이 판단은 일부만 전문가가 검토했습니다.

## 7. 자주 묻는 질문

**기사가 자동으로 바뀌나요?**
원본 파일은 바뀌지 않습니다. 검토 뒤 수정안을 반영한 변경본을 대화에 보여 주지만 제안일 뿐이며, 원고 파일을 고치거나 발행하지 않습니다. 파일 저장은 요청할 때만 새 이름으로 합니다. 적용 여부는 기자와 편집 책임자가 정합니다.

**어느 언론사의 문체인가요?**
특정 언론사나 기자의 문체를 기준으로 삼지 않습니다. 표현의 자유를 지키면서 근거가 있는 부분만 최소로 고치도록 제안합니다.

**비용이 드나요?**
이 도구는 MIT 라이선스의 공개 소프트웨어입니다. Claude Code 사용 요금은 별도이며, 금액은 Claude Code 제공자의 안내를 확인하세요.

**결과를 믿어도 되나요?**
참고 자료로 쓰세요. 인용된 사건번호와 구절은 원문과 대조할 수 있습니다. 그러나 적용 판단은 일부만 검증되었고 근거를 못 찾았다고 해서 안전한 것은 아닙니다. 법률 자문이 필요하면 전문가와 상의하세요.

**별이 많으면 소송에서 진다는 뜻인가요?**
아닙니다. 별은 먼저 살펴볼 순서입니다. 확률은 표시하지 않습니다.

**강한 비판 기사도 경고가 나오나요?**
불편한 주제, 날카로운 논조, 과거 분쟁 이력만으로는 경고하지 않도록 설계되어 있습니다. 구체적인 법적 쟁점이 원문 구절과 연결될 때만 표시합니다.

**오류가 나면 어떻게 하나요?**
"실제 근거 자료가 없다"는 취지의 오류라면 4절 앞부분의 색인 안내를 보세요. 설치 오류는 3절의 표를 먼저 확인하고, 해결되지 않으면 저장소 이슈에 오류 문구를 남겨 주세요. 이때 원고나 취재원 정보는 붙여 넣지 마세요.
